# API 可用性检测注解 - 改进说明

## 📋 改进内容

基于系统已有的消息状态库，对 API 可用性检测注解进行了全面改进：

### 1. 参考的系统消息实体

| 实体 | 参考内容 |
|------|----------|
| `ChatMessage` | 状态码设计（1000-发送中，2000-已发送，3000-已送达，4000-已读，5000-失败） |
| `UserNotification` | 消息级别（INFO-普通，WARNING-重要，URGENT-紧急） |
| `SystemMessage` | 优先级（1-5） |
| `MessageReceive` | 已读状态 |

### 2. 新增类

#### `ApiStatusCode` - API 可用性状态码

```java
public enum ApiStatusCode {
    // 成功状态 (2000-2999)
    AVAILABLE(2000, "服务可用", Level.INFO),
    AVAILABLE_DEGRADED(2001, "服务可用（降级模式）", Level.INFO),
    
    // 处理中状态 (3000-3999)
    CHECKING(3000, "正在检测", Level.INFO),
    RETRYING(3100, "正在重试", Level.INFO),
    
    // 失败状态 (4000-4999)
    UNAVAILABLE(4000, "服务不可用", Level.URGENT),
    TIMEOUT(4001, "服务超时", Level.URGENT),
    DATABASE_UNAVAILABLE(4101, "数据库不可用", Level.URGENT),
    REDIS_UNAVAILABLE(4102, "Redis 不可用", Level.URGENT),
    ...
}
```

#### `ApiStatusResult` - API 可用性状态响应

```java
@ApiStatusResult {
    statusCode: 2000,           // 状态码
    statusMessage: "服务可用",   // 状态描述
    level: Level.INFO,          // 消息级别
    serviceName: "订单服务",     // 服务名称
    dependencies: [...],        // 依赖服务状态
    responseTimeMs: 150,        // 响应时间
    checkTime: "2024-01-01..."  // 检测时间
}
```

### 3. 改进的异常类

`ApiAvailabilityException` 现在包含：
- `statusCode`: ApiStatusCode 枚举
- `serviceName`: 服务名称
- `dependency`: 依赖服务
- `responseTimeMs`: 响应时间
- `level`: 消息级别

### 4. 改进的切面

`ApiAvailabilityAspect` 新增功能：
- 使用统一的状态码
- 记录响应时间
- 缓存服务健康状态
- 提供健康状态查询方法

### 5. 新增健康监控端点

| 端点 | 说明 |
|------|------|
| `GET /api/health/status` | 获取所有服务健康状态 |
| `GET /api/health/status/{serviceName}` | 获取指定服务状态 |
| `GET /api/health/check` | 简化健康检查 |
| `GET /api/health/check/detailed` | 详细健康检查 |

## 📊 状态码设计

### 成功状态 (2000-2999)

| 状态码 | 说明 | 级别 |
|--------|------|------|
| 2000 | 服务可用 | INFO |
| 2001 | 服务可用（降级模式） | INFO |
| 2002 | 服务可用（部分功能受限） | WARNING |

### 处理中状态 (3000-3999)

| 状态码 | 说明 | 级别 |
|--------|------|------|
| 3000 | 正在检测 | INFO |
| 3100 | 正在重试 | INFO |
| 3200 | 等待依赖服务 | INFO |

### 失败状态 (4000-4999)

| 状态码 | 说明 | 级别 |
|--------|------|------|
| 4000 | 服务不可用 | URGENT |
| 4001 | 服务超时 | URGENT |
| 4100 | 依赖服务不可用 | URGENT |
| 4101 | 数据库不可用 | URGENT |
| 4102 | Redis 不可用 | URGENT |
| 4103 | 外部 API 不可用 | URGENT |
| 4200 | 检测器执行失败 | URGENT |
| 4300 | 服务异常 | URGENT |
| 4400 | 连续失败超过阈值 | URGENT |

## 🔄 使用示例

### 基础用法

```java
@GetMapping("/orders")
@ApiAvailable(
    timeout = 5000,
    dependencies = {"database", "redis"},
    onFailure = ApiAvailable.FailureAction.RETURN_ERROR
)
public Result<List<Order>> getOrders() {
    return Result.success(orderService.getOrders());
}
```

**成功响应：**
```json
{
  "code": 200,
  "message": "success",
  "data": [...]
}
```

**失败响应：**
```json
{
  "code": 4100,
  "message": "依赖服务 [database] 不可用",
  "data": null
}
```

### 健康状态查询

```bash
# 查询所有服务状态
curl http://localhost:8080/api/health/status

# 查询指定服务
curl http://localhost:8080/api/health/status/com.market.controller.OrderController.getOrders

# 简化健康检查
curl http://localhost:8080/api/health/check

# 详细健康检查
curl http://localhost:8080/api/health/check/detailed
```

**响应示例：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "timestamp": "2024-01-01T12:00:00",
    "status": "UP",
    "services": {
      "api": {"name": "API 服务", "status": "UP", "healthy": true},
      "database": {"name": "数据库", "status": "UP", "healthy": true},
      "redis": {"name": "Redis", "status": "UP", "healthy": true}
    }
  }
}
```

## ✅ 改进优势

1. **统一状态码** - 参考系统消息状态设计，保持一致性
2. **详细状态** - 区分不同类型的失败（数据库、Redis、超时等）
3. **消息级别** - INFO/WARNING/URGENT 便于告警分级
4. **响应时间** - 记录并返回检测响应时间
5. **健康缓存** - 缓存服务健康状态，支持查询
6. **监控端点** - 提供 REST API 查询健康状态
