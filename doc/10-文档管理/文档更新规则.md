## 📋 1. 文档体系

本项目使用 **双格式文档** 系统：

| 格式 | 用途 | 更新频率 |
|------|------|---------|
| **Markdown (.md)** | GitHub查看、快速编辑、版本控制 | 每次变更立即更新 |
| **Typst (.typ)** | 专业排版、PDF输出、打印 | 每晚统一更新 |

---

## 🔄 2. 更新机制

### 2.1 Markdown 文档更新规则

**触发条件**（满足任一即更新）：
- ✅ 代码变更影响文档内容
- ✅ 功能新增/修改/删除
- ✅ 配置变更
- ✅ 发现问题修复

**更新步骤**：
1. 修改对应的 `.md` 文件
2. 更新文件顶部的 `更新时间` 字段
3. 更新 `变更历史` 表格
4. 提交时包含清晰的变更说明

### 2.2 Typst 文档更新规则

**触发条件**：
- 🌙 每晚定时更新（如当日md有变更）
- 📦 重大版本发布时
- 🎯 需要输出PDF时

**更新步骤**：
1. 检查对应 `.md` 文件当日是否有更新
2. 同步更新内容到 `.typ` 文件
3. 更新typ文件末尾的日期
4. 编译测试typ文件确保无语法错误

## ⏰ 4. 更新流程

### 4.1 日常更新流程（md）

```
代码/功能变更
    ↓
识别影响的文档
    ↓
更新对应 .md 文件
    ↓
更新更新时间和变更历史
    ↓
提交到Git
```

### 4.2 夜间更新流程（typ）

```
每晚定时任务
    ↓
检查当日md文件变更
    ↓
同步变更到对应typ文件
    ↓
编译测试typ文件
    ↓
提交到Git
```

## 📝 5. 变更历史记录格式

### Markdown 格式
```markdown
| 版本 | 日期 | 变更内容 | 变更人 |
|------|------|---------|--------|
| v1.0.1 | 2026-04-07 | 新增xxx功能 | 张三 |
| v1.0.0 | 2026-04-06 | 初始版本 | 管理AI |
```

### Typst 格式
```typst
#v(2cm)
#align(center)[#text(10pt, font: "SimSun")[文档版本：v1.0.1 | 最后更新：#datetime.today().display()]]
```

## ⚠️ 6. 注意事项

### 6.1 Markdown 更新注意事项
- ✅ 保持格式一致
- ✅ 更新所有相关章节
- ✅ 更新版本号
- ✅ 填写变更人

### 6.2 Typst 更新注意事项
- ✅ 确保typ语法正确
- ✅ 编译测试通过
- ✅ 保持与md内容同步
- ✅ 更新日期戳

### 6.3 Git 提交规范
```
docs(<文档名>): <变更说明>

- 更新xxx章节
- 新增xxx内容
- 修复xxx错误
```

示例：
```
docs(部署指南): 新增Docker Compose部署方式

- 新增docker-compose.yml配置
- 更新部署步骤章节
- 更新版本到v1.0.1
```
